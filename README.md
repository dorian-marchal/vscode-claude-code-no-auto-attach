A personal VS Code extension that patches the installed Claude Code extension to fix annoyances upstream hasn't addressed yet:

- **Auto-attach defaults to OFF.** Stops Claude Code attaching the current file/selection to every prompt. Addresses [anthropics/claude-code#24726](https://github.com/anthropics/claude-code/issues/24726). Configurable via `claude-code-no-auto-attach.detachContextByDefault` (set to `false` to keep upstream's attached-by-default behavior). 2.1.269 replaced the composer's attach toggle with a chip you dismiss with an X, so the patch gates the attachment at send time instead — the chip stays, and says which file is current whether or not it rides along.
- **Click the file chip — or Ctrl+F — to toggle context attachment.** The composer's file chip is a toggle again: click it to attach/detach the current file/selection (orange = attached, dimmed = not), and `Ctrl+F` does the same with a Claude session focused — independent of the default above. 2.1.269 made the chip a static label with a dismiss X, which left only the shortcut. The X keeps upstream's own behavior (it removes the chip); re-attaching afterwards clears that dismiss memory and republishes the selection the IDE last reported.
- **No permission-mode pill.** The Plan/Auto/Bypass permissions button is hidden from the composer footer, which 2.1.269 crowded with an agent-map pill and a prompt-cache clock. `Shift+Tab` still cycles modes, and the send buttons are trimmed from 26px to 22px for the same reason.
- **Optional auto-allow for Claude's own files.** In `bypassPermissions` mode, Claude Code still prompts when a tool call touches its own protected paths (e.g. project `.claude/`, `~/.claude/settings.json`). Set `claude-code-no-auto-attach.autoApproveProtectedPathWrites: true` to silently approve `Write`/`Edit`/`MultiEdit`/`NotebookEdit`/`Bash` prompts. Addresses [anthropics/claude-code#37029](https://github.com/anthropics/claude-code/issues/37029).
- **Session-scoped model switching.** Upstream, picking a model in the UI rewrites the global default in `~/.claude/settings.json`, so every future session inherits it. The patch reroutes the switch through the SDK's session-scoped `set_model` control request: switching only affects the current session, new sessions start on your real default.
- **Reopened sessions keep their effort.** A session-scoped effort only lives in the running CLI, so a session brought back with `Claude Code: Reopen Closed Session` (or any resume) would come back at the default effort. The CLI brings the model back by itself, and it records each turn's effort in the transcript without reading it on resume, so the patch puts that effort back: right after launch, the session gets the effort of its last answer, and the badge and effort picker show it. A session that never changed its effort is left alone.
- **Per-session model badge.** Each Claude session webview shows the current model in a badge (top-right), colored like the quick-send slot the session is on (same model, and same effort unless the slot leaves effort alone), else per model family (Haiku teal `#269473`, Sonnet gold `#bc8e26`, Opus red `#c63e3e`, Fable purple `#8052d2`; falls back to the default badge color otherwise). When the current model supports effort, the badge also shows the current effort level (e.g. `Opus 4.8 · xhigh`, or `· ultra` under ultracode) and updates live as the effort changes. Click it to apply the next quick-send slot, like `Ctrl+M`. Being per-webview, it stays correct with many concurrent sessions. The badge shows what the session actually runs: when the last answer came from a different model family than the picker's selection — typically a resumed session, whose `modelSelection` is seeded from the global default while the CLI keeps the session's own model — the badge names and colors the model that answered (as upstream's footer label does) and the tooltip notes that the picker's value was never applied to this session. A plain model switch clears the last-served model, so it never causes this.
- **Quick-send slots.** Four slots, each a model + effort pair you pick in the settings (`quickSend.<slot>.model` / `quickSend.<slot>.effort`), read at runtime so a change applies to open sessions without a reload. Defaults: **purple** Fable · `high` (`Ctrl+0` + button), **red** Opus · `xhigh` (`Ctrl+1`, no button), **yellow** Sonnet · `medium` (`Ctrl+2` + button), **teal** Haiku · `medium` (`Ctrl+3` + button). Applying a slot switches the session's model and sets the slot's effort, both session-scoped (via `sessionScopedModelSwitch` / `sessionScopedEffortSwitch`), so your global defaults never change. The effort is skipped when the model doesn't support that level, or when the slot's effort is `unchanged`. A slot whose model isn't available for the session is skipped. Model lookups skip alias entries — the older spellings Claude Code lists last in its picker since 2.1.261 — so a family lands on its current spelling.
- **Ctrl+0/1/2/3 send with a slot.** With a Claude session focused, `Ctrl+0`…`Ctrl+3` apply that slot, then submit the composer in one keystroke (the keyboard equivalent of the quick-send buttons). No-op while the session is busy, when the composer is empty, or when the slot's model isn't available.
- **Ctrl+M cycles slots.** With a Claude session focused, `Ctrl+M` (or a click on the badge) applies the next slot, in shortcut order, without sending.
- **Quick-send buttons.** Three extra send buttons sit next to the composer's send button — yellow, teal and purple, one per slot — that apply their slot, then submit the prompt in one click. Each button's tooltip shows the slot's model, the effort it will set, and its shortcut (e.g. `Send to Sonnet · medium [Ctrl + 2]`). Each button hides when its slot's model isn't available; the original send button keeps its native send/stop behavior.
- 🪲 **Slash commands keep your file context.** Upstream silently drops the current file/selection for *any* message starting with `/` (the flag is computed as `!startsWithSlash`, and before 2.1.270 as `includeSelection && !startsWithSlash`), so invoking a skill or slash command never shows the agent your open file even when the chip says it is attached. The patch makes the chip authoritative: if context is on (default or `Ctrl+F`), it rides along with slash commands too. Explicitly attached files (`@`-mentions / attach button) were never affected.
- 🪲 **New sessions focus the composer again.** Since 2.1.257 the focus-on-mount effect is gated on `document.hasFocus()`, which a freshly opened Claude tab never satisfies (VS Code's focus lands on the webview shell before the app's iframe exists), so the input stays unfocused. The patch restores the pre-2.1.257 direct focus call, which pulls focus into the webview by itself — exactly the old behavior, including for session switches.
- **Every question takes free-text notes.** `AskUserQuestion` only accepted free text through the "Other" option, i.e. *instead of* a choice — picking an option and adding a caveat was impossible. Every question now ends with an "Add notes (optional)…" box you can fill in alongside your pick (or on its own). The notes reach the model through the tool's own `annotations[question].notes` field, which the CLI already supported and renders next to the answer (`"Which library?"="date-fns" notes: only if it tree-shakes`) — and, because notes are present, it tells the model to read the answer carefully instead of treating it as a plain pick. Notes without a pick are sent as the CLI's `(notes only)` answer, so the submit button unlocks. The box is hidden while "Other" is selected (that option shows the same box inline, backed by the same text, so nothing is lost switching between them). `Enter` submits, `Shift+Enter` breaks a line; other keys stay inside the box. Notes also reach the model when a question is asked again after a reload: upstream then sends the answers as a plain "Answering your earlier question…" prompt built from the picks alone, so the notes are merged into it (`"Which library?": date-fns — notes: only if it tree-shakes`). And picks and notes survive the dialog being hidden: upstream hides it while the composer text is changing (e.g. a dictation cleanup landing) and brings it back empty.
- 🪲 **Answering a question no longer jumps to the next one.** In a multi-question dialog, picking an option scrolled on to the next question 300ms later — so the question you just answered (and its notes box) was gone before you could annotate it. The jump is dropped; the nav tabs, which mark answered questions, and `ArrowLeft`/`ArrowRight` still move between them. Submitting is unchanged: it stays gated on every question having an answer.
- 🪲 **Questions don't steal your focus.** When Claude asks a question (`AskUserQuestion`), the widget focuses its first option with a bare `.focus()`, which pulls window focus into the Claude panel — so a question arriving while you type in an editor or terminal swallows your keystrokes. The patch gates that on `document.hasFocus()`: the option is focused only when focus is already inside the panel, and arrow-key navigation between questions is unchanged.
- 🪲 **No usage-limit nagging.** The "You've used 75% of your session limit · resets in 2h" / "Approaching weekly limit" banner fires on every rate-limit event and has to be dismissed by hand each time. The patch suppresses it. The hard "You've hit your <limit>" banner (status `rejected`) is kept — at that point you're actually cut off, so it's worth a click.
- 🪲 **Capped, scrollable prompt bubbles.** A huge pasted prompt (e.g. a long stack trace) no longer fills the whole webview — rendered user prompts are capped at `40vh` and scroll instead. Short prompts are unaffected.
- 🪲 **Skill and command prompts get the normal prompt bubble.** Upstream draws any prompt starting with `/` as a bare box, with no message actions (so no fork or rewind) and no "Show more" fold, so a long skill prompt took as much room as it needed. The patch sends these prompts through the normal bubble, showing the same `/name args` text the bare box showed.
- **Edit a prompt in the same tab.** In an editor tab, hovering a prompt shows a pencil button left of its message actions arrow. One click makes the same fork as the arrow's "Fork conversation from here" (the conversation up to just before that prompt, with the prompt back in the composer to edit), but shows it in the current tab instead of opening a new one, as the sidebar already does. The original conversation is not closed or lost: it stays in the session history. The button is hidden in the sidebar, where the stock entry already works this way.
- **`vscode://…/open` URIs open in your locked Claude editor group and auto-send.** Claude Code's (undocumented) URI handler — `vscode://anthropic.claude-code/open?prompt=<text>&session=<id>` — opens the session with `claude-vscode.primaryEditor.open`, i.e. in the **active editor group** (since 2.1.261 upstream first looks for a group whose tabs are *all* Claude panels, which a single dropped file defeats), so following a link hijacks whatever group you were working in. The patch routes it through `claude-vscode.editor.open` (the command behind "open Claude in an editor") with the target column resolved by the patch, and locks the group afterwards, so the session lands in the editor group you keep Claude in. A prompt is also **submitted right away** once the session is idle, instead of just being typed (gives up after 30s and leaves the prompt typed). Configurable via `uriOpensInEditor` and `uriAutoSendsPrompt`; turning the first off restores upstream's active-group behavior.
- **A trimmed IDE system prompt.** The Claude Code extension appends a `# VSCode Extension Context` block to every session. Two of its rules are rewritten: the **"Who you are writing for"** section (new in 2.1.270) is dropped — it makes the model open ordinary replies with a `Written for: …` line, though the rule is meant for pieces written for a third party — and the link rule is flipped from **workspace-relative to absolute paths**, which is the only way a file outside the workspace root (a worktree checked out beside it, say) can be named at all. The sections that earn their place are kept: `Code References in Text` (what makes paths clickable), `User Selection Context`, and `Focus view in this editor` (load-bearing — it overrides the terminal Focus-mode rules that also reach the prompt).
- **Dictated prompts are cleaned up by Haiku.** When a Claude Code dictation stops (the mic button is no longer blue), the dictated text goes to Haiku, which removes fillers ("uh", "um", "you know"), stutters, repeated words and false starts, fixes words the speech-to-text clearly broke, and joins fragments into full sentences. Nothing else is rewritten, and a question or request in the transcript is cleaned, never answered. It runs Claude Code's own `claude` binary with your login, so no API key is needed, and takes about a second: the process boots while you speak, and thinking is off (with it on, Haiku alone took ~3.8s). The composer pulses meanwhile. Only the dictated part is replaced, text you had before or after it stays as is. Sending while recording or while the composer pulses (Enter or the send button) waits for the cleaned text and then sends it, or sends the raw text if it has not landed within 3s. Text you type around the dictated part before the result lands is kept (so you can pick up by typing instead of stopping the mic); editing the dictated part itself, sending or recording again keeps the raw text. `Cmd+Z` brings the raw text back afterwards. Configurable via `voiceCleanup.enabled`.
- **Dictation uses the Mac's built-in mic.** Claude Code records from the system's default input, so a plugged-in headset mic wins. While a recording runs, the patch switches the default input to the built-in mic, then puts the previous one back when it stops (unless you changed it meanwhile). Once the patch has checked that the recording really reads the built-in mic, the mic button turns green instead of blue. If it stays blue, the switch did not work, and the log names the input it records from. Configurable via `dictation.builtInMicrophone`; macOS only.
- **Other extensions can close a session tab.** The patch exposes `globalThis.__ccaaClosePanel(sessionId)` to the extension host every window runs, so another extension in the same window can close one Claude session — att uses it to cut the session when you archive or delete its card. A session's tab is only reachable through Claude Code's own `sessionId -> panel` map: from outside, every session tab is the same `claudeVSCodePanel` webview. Closing goes through the panel's `dispose()`, i.e. exactly what the tab's own X does — the session is cut and stays in `Claude Code: Reopen Closed Session`. A window that doesn't hold the session answers `false`, so callers can try every window.
- 🪲 **Markdown previews are picked up as context.** A markdown *preview* isn't a text editor, so focusing it left Claude Code with no current file — you had to switch back to the raw `.md`. The patch handles both of VS Code's preview implementations: the custom-editor preview (`vscode.markdown.preview.editor` / `vscode.markdown.editor`, e.g. when `*.md` is associated with it) exposes its source `.uri` directly, so it's read straight off the tab; the classic "Open Preview" webview doesn't, so its source is resolved from the tab label (preferring the last active markdown editor, then a uniquely-matching open document, then a unique workspace file). Either way the resolved file is attached as the current-file context.

## How it works

On activation, the extension iterates every installed `~/.vscode/extensions/anthropic.claude-code-*` directory and applies independent sub-patches to three files (a sub-patch whose anchor no longer matches is skipped and logged without blocking the others):

- **`webview/index.js`**
  - finds the submit handler's include-selection computation — `let n=!t`, where `t` is "message starts with `/`" (up to 2.1.263 it also carried the composer toggle, as `let gt=v&&!De`) — and replaces it with a read of one global, `(globalThis.__ccaaContextOn??!1)`, or `??!0` when `detachContextByDefault` is off. That flag is the third argument of `session.send(text,files,includeSelection,…)`, which is the only thing deciding whether `selection.value` is attached, so the one edit covers both features: context is detached by default, and the slash-command drop is gone (the toggle alone decides). `??` and not `!!`, so the default still holds if the Ctrl+F patch below was skipped. The original expression is parked in a `/*__ccaaSlashSel:…*/` sentinel comment for a byte-exact revert;
  - exposes `globalThis.__ccaaToggleContext` from the model-UI effect (where the session object is in scope), seeds the flag there, and binds `Ctrl+F` in that patch's existing capture-phase keydown listener. The toggle also mirrors the state onto `document.body.dataset.ccaaContext` for the CSS below, and — when context is turned back on after the chip was dismissed — clears upstream's `dismissedSelection` memory (which would otherwise swallow the next update for the same file) and republishes `context.currentSelection`. Note this gates at *send* time and deliberately leaves the selection itself alone: holding it back at the session (`applySelectionUpdate`) also removes the composer's file chip, which is the only way to see which file is current and is what the X button acts on;
  - inserts `onClick`/`onMouseDown`/`style` props on the composer's file chip — anchored on the static chip (`footerButtonStatic` in its className, immediately followed by the `Showing Claude your current file selection (…)` tooltip), so the pre-2.1.269 shape, a *button* with an `onClick` of its own that an injected one would override, matches nothing and is skipped. The click calls `globalThis.__ccaaToggleContext?.()` — the same global `Ctrl+F` flips, a no-op if that patch skipped — `onMouseDown` is cancelled so clicking the chip doesn't blur the composer, and `cursor:pointer` is set inline here rather than in the CSS file so it can't promise a click this patch didn't add. The X button is left untouched. The props are wrapped in a `/*__ccaaChipClick*/…` sentinel for a byte-exact revert;
  - appends to the reactive effect that registers the "Switch model…" command action: a DOM badge kept in sync with the session's `modelSelection` (and its `effortLevel`/`currentModelSupportsEffort`/`ultracodeEnabled` signals, so it shows `Model · effort` when the model supports effort and re-renders on effort changes). The badge is a single pill (`#ccaa-model-badge-main`). Its model is `lastServedModel` whenever that disagrees with `modelSelection` by family — upstream clears `lastServedModel` inside `setModel`, so while it is set no switch was requested and the next answer comes from that model, whereas `modelSelection` is seeded from the global default on launch and can name a model the CLI never received (a resumed session); `currentMainLoopModel` keeps the pre-switch value and is used solely as a color hint when neither carries a family (`default`). The effort suffix follows the shown model's `supportsEffort`. The badge color is the slot `__ccaaSlotIndex(session,shownModel)` finds, else the family color, and a click calls `__ccaaCycleSlot` (the model picker if the slot helpers are missing); two tooltip helpers (`__ccaaShowTip(el,text)`/`__ccaaHideTip()` position a single reused `#ccaa-tip` node above a hovered element — instant, unlike the native `title` delay — used by the quick-send buttons); plus a capture-phase keydown listener — `Ctrl+M` calls `__ccaaCycleSlot`, and `Ctrl+0`…`Ctrl+3` call `__ccaaSendWithSlot` for the slot bound to that digit. The listener is bound once per webview, so the effect leaves the session and the shown model in `globalThis.__ccaaSession`/`__ccaaBadgeShown` for it;
  - finds the unique rate-limit banner construction in the `rate_limit_event` handler and gates it on `info.status==="rejected"`, so only the hard limit-reached banner survives; the original call is parked inside a `/*__ccaaRateLimit*/…*/` sentinel for a byte-exact revert. Three bundle generations are matched: 2.1.251+ routes the event through a `"clear"/"show"/"keep-hidden"` decision helper and builds the banner in the `"show"` branch — assigned directly (`let Q=zQ0(Y);this.rateLimitWarning.value=Q,this.shownRateLimitKey=…`) in 2.1.251, and since 2.1.257 to `frameRateLimitWarning`/`shownRateLimit` inside a signal batch (`let Q=uZ0(Y);$H(()=>{this.frameRateLimitWarning.value=Q,…})`); 2.1.280 passes the builder a second argument (`vT0(Y,this.config.value?.experimentGates[…])`), matched optionally; older bundles assigned it directly behind a `dismissedRateLimitKey` check;
  - registers (editor panels only, at the app bootstrap where the session store is in scope — an IIFE passed as a second, ignored argument to the `listSessions("panel_boot")` call, because the statement around that call keeps changing shape: a plain statement up to 2.1.257, an `if(…)` operand in 2.1.261, an assignment inside one since 2.1.270, where a leading comma would have silently stolen the assignment's value. An argument list is an expression position whatever surrounds the call) a window `message` listener for the custom `ccaa-open` message posted by the extension.js uri-open patch. The extension has already opened the panel on the right session, so the listener only finishes the job: it types the prompt via the stock `initialPrompt` signal when the extension could not hand it to the stock command (`typePrompt`, set when the session already had a panel), and — when `autoSend` is set — polls until the prompt has reached the composer, the session is idle and the send button is enabled, then `requestSubmit()`s the composer (30s timeout; also aborts if the session is switched). The message is ignored until the panel actually shows the URI's session (`match`), which is what keeps a broadcast landing in a single panel; `strict` (set only for that broadcast) gives the match 5s before the panel rules itself out. A nonce set dedupes the extension's delivery retries, the side bar ignores the message (`window.IS_SIDEBAR` gate), and the stock webview listener never sees this type at all.
  - finds the unique session-mount focus effect (`if(nk(document.activeElement))return;jV1(()=>q.current?.focus(),()=>J.ambientFocusAllowed())`, keyed on `sessionId`) and replaces the gated `jV1(...)` wrapper with the bare `q.current?.focus()` it wraps — the composer's stock focus handle, which still goes through `safeFocus`. The wrapper is parked in a `/*__ccaaMountFocus:…*/` sentinel comment for a byte-exact revert;
  - finds the unique question-option auto-focus (`b.querySelector('[role="radio"], [role="checkbox"]')?.focus()`, the effect keyed on the question index) and prefixes it with `document.hasFocus()&&`, parked in a `/*__ccaaAskFocus*/` sentinel for a byte-exact revert. Every other permission request already goes through `safeFocus` plus a `document.hasFocus()` gate; this one did not;
  - adds the per-question notes box to the same widget, as three edits that only apply together (a notes box that never reaches the model would be worse than none): the JSX one anchors on the "Other" option's inline text input (since 2.1.285 passed as the `children` of an option component instead of sitting inline) and appends a sibling at the end of the option list, hidden while "Other" is selected and bound to the very same `[question -> text]` state — so no extra hook is added and the text survives selecting/deselecting "Other"; the data one wraps the argument of the effect that reports `{questions,answers}` back to the permission dialog (`/*__ccaaAskNotesOut*/((__ccaaP)=>{…})(<original>)`, the original expression sitting where the revert regex can read it back) so it also carries `annotations[question]={notes}` for every question whose box has text and no "Other" pick, and fills that question's answer with `(notes only)` when nothing was picked — the dialog's submit button is gated on every question having a non-empty answer, and `(notes only)` is the sentinel the CLI already maps to "(no option selected)". The same wrapper saves the picks and the text in a `WeakMap` keyed on the question's input object (`globalThis.__ccaaAskDrafts`). The third edit covers a question still open when the session reloads: upstream asks it again locally and sends the answers as a new prompt, through a function that reads only `answers` (`function(p){let a=p.answers??{},r=[];for(let q of p.questions??[])…`). The edit reassigns that function's input first (`/*__ccaaAskNotesReplay*/p=(…)(p);`), appending ` — notes: <text>` to each answer that has notes and turning `(notes only)` into `(no option selected)`. The box's keydown stops every key from reaching the option list's arrow/digit handling except a plain `Enter`, which is left to bubble to the dialog that owns submit;
  - seeds the same widget's picks and notes states from that saved draft, so they survive a remount. The dialog is only mounted while `promptInputActive` is off, and any composer text change sets it for 1.5s, so the dialog comes back as a new component with no picks and empty notes. Anchored on the picks initializer (`useState(()=>{let r={};if(input.answers&&input.questions)…return r})`) and the `[texts,setTexts]=useState({})` right after it, it returns the saved picks first (`/*__ccaaAskDraftSel*/`) and turns `{}` into `()=>saved?.texts||{}` (`/*__ccaaAskDraftText*/`). It is its own sub-patch: without it, notes are still sent, only lost on a remount like upstream's picks;
  - finds the unique auto-advance clause in the same widget's select handler (`else if(confirming===null&&input.questions&&index<input.questions.length-1)…setTimeout(…,300)`) and parks the whole clause in a `/*__ccaaNoAdvance:…*/` sentinel comment, which both removes it and makes the revert byte-exact. It is the trailing arm of an `else if` chain, so dropping it leaves the chain valid;
  - finds the unique composer send button (`type:"submit"` + `className:X.sendButton` + `data-permission-mode`) and inserts three `type:"button"` siblings after it (the yellow, teal and purple slots, tagged `data-ccaa-slot`) that read their slot on every render and on click call `__ccaaApplySlot`, then `requestSubmit()` the form. Each carries an `aria-label` and an instant custom hover tooltip (via `__ccaaShowTip`/`__ccaaHideTip`) reading e.g. `Send to Sonnet · medium [Ctrl + 2]`;
  - lets the launch-time applied-settings read-back adopt a restored effort. Since 2.1.270 the resumed session's first read passes `{effort:!1}`, so the webview keeps the effort it seeded from the host config — the global default. Anchored on the unique `if(opts.effort!==!1&&this.effortChangeCount===count)this.adoptAppliedEffort(applied)`, it adds an `applied?.ccaaEffortRestored===!0&&this.effortChangeCount===count||` branch in front. Since 2.1.284 the read always calls `this.adoptAppliedEffort(applied,{level:opts.effort===!1||this.effortChangeCount!==count,…})`, where `level` means "skip the level", so there the same test goes in front of that flag as `…?!1:`. Either way only an answer the host tagged (see `extension.js` below) opens it up, and a pick made during the read still wins. Older bundles adopt the effort on every read and skip this;
  - sends prompts starting with `/` through the normal prompt bubble, with two edits. The `if(item.isSlashCommand)return <bare box>` branch of the `case"text"` arm gets a `/*__ccaaSlashBubble*/!1&&/*__ccaaSlashBubbleEnd*/` guard, so it falls through to the bubble with the message actions (fork, rewind) and the "Show more" fold. The `isSlashCommand&&recordDetail` notice that 2.1.285 added in front of it is left alone. The memo that feeds that bubble its text (the `.map` calling the pasted-content expander on each text block) wraps the expander's result in a function that turns `<command-name>X</command-name><command-args>Y</command-args>` into `X Y`, like upstream's own parser does for the bare box, and only when the result starts with `/`. The fork prompt is already built from that parsed text, so it is `/name args` too.
  - adds an **Edit prompt in this tab** pencil button before the message actions arrow (`title:"Message actions"`), in the same absolutely positioned container, so it is placed with an inline `position:absolute;right:24px` and reuses the arrow's own className template to show and hide with it (hidden behind `!window.IS_SIDEBAR`). One regex spans the arrow and the menu's `Fork conversation from here` entry, which is where the button takes the entry's click handler from. Its click raises `globalThis.__ccaaForkHere` and calls that handler. Two reads of `config.value?.openNewInTab`, the flag that sends a fork to a new tab, get a `!globalThis.__ccaaForkHere&&` guard: the one in the webview context's `forkConversation`, which then takes upstream's own `viewSession(forkId,prompt)` branch (the sidebar's path: the panel switches to the fork, and the host rebinds the tab to the session the panel reports), and the one in `startNewConversationTab`, which a fork from the first prompt goes through, and whose `false` makes the caller create the new session in place. Both reads run before the fork's first `await`, so the flag is lowered in a `finally` right after the call. All three edits sit in `/*__ccaaForkHere*/…/*__ccaaForkHereEnd*/` sentinels and only apply together;
  - puts the quick-send helpers at the very top of the bundle (no anchor, so they always land and exist before anything renders). `__ccaaSlots(session)` reads the slot settings from the webview state (`session.config.value.ccaaQuickSend`, see `extension.js` below) over the built-in defaults. `__ccaaSlotTarget` finds a slot's model: an exact `value` first, else the first non-alias model whose value/name contains the slot's word. `__ccaaSlotEffort` gives the level to set, or null for `unchanged` or a level the model doesn't list. `__ccaaApplySlot` calls the session's `setModel` (skipped when `__ccaaNeedsSwitch` says it already runs that model), then `setEffortLevel`. `__ccaaSlotIndex` finds the slot the session is on (the last one applied wins a tie), `__ccaaCycleSlot` applies the next available one, and `__ccaaSendWithSlot` applies one and submits the composer (found via the `button[type="submit"][data-permission-mode]` send button, skipped while busy or when it is disabled). `modelSelection` alone can't tell whether a switch is needed: it is seeded from the *global* default model setting on launch — which the session-scoped `setModel` patch never writes — so a resumed session reads e.g. `opus[1m]` while the CLI still serves Fable, and the send would keep the old model yet apply the slot's effort. `lastServedModel`/`currentMainLoopModel` are the drift check;
  - hands the composer's dictation state to the voice-cleanup lib just before the helper that wipes it runs (`function <name>($){$.gen++,$.prefix=null,$.suffix="",$.lastSetInput=null}`, called on stop, at the end of the stream and when you type over a recording): `prefix`/`suffix` are the text before and after the caret when recording started, `lastSetInput` the last text dictation wrote. The call is a `/*__ccaaVoiceSnap*/` block at the start of the function body;
  - puts the voice-cleanup lib at the top of the bundle, right after the quick-send helpers (no anchor). It saves that state, and listens for the top-level `ccaa-voice` messages the `extension.js` hooks below post: `cleaning` makes the composer (`[role="textbox"][aria-label="Message input"]`) pulse through the Web Animations API, `done` carries Haiku's text, `failed` and `skipped` (no cleanup runs: setting off, empty transcript, no binary) just stop the pulse. The dictated part is the text between `prefix` and `suffix` in `lastSetInput`. The result lands as long as the composer still holds that part unchanged: at its own place (right after `prefix`), else as its only copy, so text typed around it in the meantime is kept. When it is edited or gone (sent), or while a new recording runs, the result is dropped. It replaces the dictated part only, keeping its leading and trailing spaces. With the composer focused the swap is a select-all + `execCommand("insertText")`, which is undoable, then the caret goes to the end of the cleaned part, or stays in the typed text when it was there; otherwise `textContent` is set and an `input` event dispatched so the composer's state follows. A stop click saves the state before `cleaning` arrives, the end of the stream only after it, so `cleaning` leaves the saved state alone. A send made while recording (the mic button reads `Stop recording`), while the composer pulses or while a send is already held is caught by `window` capture listeners before Claude Code sees it: an Enter keydown in the composer, or the submit of the form around it. Holding it stops the recording through the dictation shortcut (a non-bubbling `d` keydown on the document with both `metaKey` and `ctrlKey`, which covers macOS and the others). Any message but `cleaning` replays it right after the cleaned text is applied: the same Enter keydown on the composer, or `requestSubmit()` on the form. So does a 3s cap, which sends the raw text. Typing in the composer while it is held drops it. The quick-send buttons and shortcuts are not held.
- **`webview/index.css`**
  - appends a rule capping the user prompt bubble at `max-height:40vh` with `overflow-y:auto`. It targets the bubble via a hash-independent attribute selector (`[class*="userMessage_"]`) and is appended last so its equal-specificity `overflow-y` wins over upstream's `overflow-y:hidden`.
  - appends two rules keying off `body[data-ccaa-context]` (set by the Ctrl+F patch) that colour the composer's file chip orange while context is on and dim it to `.45` while it is off — the chip is always rendered now, so this is what makes the attach state visible. No marker is set if that patch skipped, and the chip then keeps its stock appearance;
  - while `body[data-ccaa-mic="builtin"]` is set (see the built-in mic hooks below), sets the recording button's `--app-recording-foreground`/`--app-recording-background` to `--vscode-charts-green` instead of upstream's blue;
  - appends `[title*="Shift+Tab to cycle"]{display:none!important}` (plus a `div:has(>…)` rule for its wrapper, so the footer's flex gap leaves no hole) to hide the permission-mode pill, and `[class*="sendButton_"]{width:22px;height:22px}` to trim the send buttons — upstream's and the three injected next to it — from 26px. Both are matched by the tooltip text / hash-independent class, and are no-ops if either changes;
  - appends `[class*="footerButton_"]>span{max-width:min(200px,14vw)}` to keep the model picker on the composer footer row. The footer measures its children and, once they stop fitting, moves the model pill to a row of its own; upstream's 200px cap on the file-selection label — plus the extra send buttons injected above — was enough to trigger that on a long file name in a narrow panel. The viewport-relative cap makes the label give way first (the full name stays in the button tooltip). Same hash-independent selector trick, and a no-op if the footer markup changes.
- **`extension.js`**
  - finds the unique `can_use_tool` site and injects an early return that approves Write/Edit/MultiEdit/NotebookEdit/Bash when `autoApproveProtectedPathWrites` is on;
  - captures permission-mode changes into `globalThis.__ccaaPermissionMode` to gate the above;
  - replaces the body of the `set_model` handler — upstream's `writeUserSettingsAndPush({model})` (which persists to `~/.claude/settings.json`) — with `withChannel(...query.setModel(...))`, the session-scoped control request, when `sessionScopedModelSwitch` is on. Since 2.1.261 the stock response also carries the CLI's `applied` settings (the webview adopts `applied.effort` after a switch, e.g. a per-model effort from `modelSettings`), so the patched path reads them back with `query.getSettings()` and returns them the same way (best effort — the switch never depends on it). That read-back is raced against a 200ms timeout, and the response goes out without `applied` when it loses: the quick-send shortcuts wait for the whole switch before submitting, so every millisecond here is a millisecond before the message leaves. The anchor pins the `writeUserSettingsAndPush(channel,{model:…})` statement rather than the method signature: 2.1.270 put a malformed-request guard in front of it, and the early return has to land after that guard anyway;
  - makes effort switching session-scoped when `sessionScopedEffortSwitch` is on: in the `apply_settings` handler, any effort-only settings object (single key `effortLevel`, sent both by the native effort picker and by the quick-send slots) is forced to `flagsOnly`, so `writeUserSettingsAndPush` skips the `~/.claude/settings.json` write but still pushes the effort to the running session via `applyFlagSettings`. Since 2.1.257 `applySettings` takes a 4th `scope` argument (`"localSettings"` writes the project's `settings.local.json` and rejects `flagsOnly`), so the override only fires when no scope is passed — the effort picker never passes one. The flip is anchored on the `writeUserSettingsAndPush` statement, not the signature: 2.1.270 added a prologue that derives the target settings layer from the flags argument and throws when it disagrees with the setting's own layer, and `effortLevel` is declared as `userSettings` — flipping the flag ahead of that loop would make every effort change throw;
  - restores a resumed session's effort when `sessionScopedEffortSwitch` is on. The pick above lives in the CLI's flag settings, so it is gone once the process restarts; the CLI records each turn's effort (`"effort":…` on every assistant entry of the transcript) but does not read it back. At the top of the `get_applied_settings` handler — once per channel (a `WeakSet`), i.e. on the read the webview makes right after launch — the patch finds `<sessionId>.jsonl` in the Claude projects folder (`$CLAUDE_CONFIG_DIR` or `~/.claude`, every project folder, since the session id alone is unique), reads its tail (256 KB, then 4 MB, then 16 MB) for the last main-chain assistant entry, and when the CLI applies a different effort pushes it with `applyFlagSettings({effortLevel})` and answers with `ccaaEffortRestored:true` in `applied`. A new session has no transcript yet, a session that never changed its effort already matches, and any error falls through to upstream's read;
  - rewrites the URI handler's `/open` case (anchored across the `/install-plugin` tail, whose plugins-dialog call — `notifyOpenPluginsDialog` inside an `openLast().then(…)`, since 2.1.280 a direct `openPluginsDialogInChat` — is the only in-scope reference to the webview manager; 2.1.257's session-id validation guard is matched optionally and kept ahead of the injected code): when `uriOpensInEditor` is on, it runs `claude-vscode.editor.open` instead of `primaryEditor.open` (which targets `ViewColumn.Active`), passing the Claude group's column and locking that group afterwards, then posts a custom top-level `{type:"ccaa-open",prompt,match,typePrompt,strict,autoSend,nonce}` message to the panel it just opened, retrying every 500ms for ~15s because the panel may still be booting.
    - *Which group.* Stock's own rule — a group whose tabs are **all** `claudeVSCodePanel` webviews — loses the group the moment a file is dropped into it, and then banishes the session to a fresh column. The patch instead takes the group holding the most Claude sessions (ties → rightmost) whatever else sits in it, and failing that an open-but-empty group: the API exposes no lock state (`TabGroup` has no `isLocked`), but VS Code only keeps an empty group around when it is locked, which is exactly the empty Claude group waiting for a session. With neither, the column is left undefined and stock creates + locks one.
    - *Side effect.* Since 2.1.257 `claude-vscode.editor.open` also records `claudeCode.preferredLocation = "panel"` whenever it is called with a non-active column, exactly as when you open Claude in an editor by hand — so a URI opened this way also makes the editor the preferred location.
    - *The lock.* Stock only locks a group it had to create, so reusing a group that got unlocked would leave it unlocked. The panel takes focus (`createWebviewPanel` gets a bare `ViewColumn`), so the group it landed in is the active one: if it holds a Claude session and is not the last remaining group — locking that one traps the editor — `workbench.action.lockEditorGroup` runs, which is a no-op when it already is locked. Upstream's `claudeCode.lockEditorGroups` (2.1.274+) set to `false` skips it, as it skips stock's own lock.
    - *Which webview.* The target is found by diffing the manager's `webviews` set around the open call, so the message is pinned to one panel. When the session already had a panel nothing is added — it is only revealed, and the stock command drops the prompt ("Session is already open…") — so the prompt is withheld from the command (no warning), `typePrompt` is set and the message is broadcast to the chat webviews with `strict`, the session id in `match` picking the one panel showing it. Un-patched webviews ignore the unknown message type (the stock listener only handles `from-extension`), so a partial patch degrades to a no-op. The original `primaryEditor.open` call is kept as the fallback when the setting is off or anything throws;
  - rewrites two passages of the `# VSCode Extension Context` system prompt the extension appends to every session (one template literal, with real newlines — esbuild does not escape them): the `## Who you are writing for` section, matched from its heading up to the next `## ` heading, is replaced by nothing, and the `The URL links should be relative paths from the root of  the user's workspace.` line (double space is upstream's, matched as `\s+`) by an absolute-path rule. Since this *removes* text there is no injection to park in a sentinel, so the literal is split and the original kept in a dead branch instead — ``…before` + /*__ccaaPromptEdit*/(0?`original`:`replacement`) + /*__ccaaPromptEditEnd*/ `after…`` — which the model never evaluates and the revert splices back into a single literal, byte for byte. Each edit needs exactly one match and is applied on its own: 2.1.263 has no `## Who you are writing for` section, so that edit finds nothing and is left out while the link rule still applies. The sub-patch fails only when neither edit lands, and an original holding a backtick, a backslash or a `${…}` placeholder bails out rather than being parked into something that would mean anything else;
  - exposes `globalThis.__ccaaClosePanel(sessionId)` — `sessionPanels.get(id)?.dispose()`, returning whether a panel was closed — from a field of its own injected beside the webview manager's `sessionPanels=new Map` declaration. A class field initializer runs with `this` bound to the instance, so the arrow function closes over the manager without depending on its minified name or on any method around it; the field's terminating `;` sits inside the sentinel, so stripping the block leaves the next field declared as before. Disposing the panel is upstream's own close path (`onDidDispose` shuts the session's channels down and files it under "Reopen Closed Session"), so nothing here reimplements teardown;
  - in the `onDidChangeActiveTextEditor` handler, when `activeTextEditor` goes undefined and the active tab is a markdown preview, resolves the source `.md` and pushes it as the current-file context (the same `{filePath,startLine,endLine}` shape upstream produces for an unselected file) instead of clearing it. Two preview kinds are covered: a custom-editor preview (`TabInputCustom`, viewType `vscode.markdown.*`) exposes `.uri` so the path is read directly; the classic webview preview (`TabInputWebview`, viewType `markdown.preview`) has no uri, so the source is resolved from the tab label's basename — preferring the last active markdown editor, then a unique open markdown document, then a unique `findFiles` match. Two more insertions: one at the top of the handler records the last active markdown editor, and one pushes an extra disposable next to the `onDidChangeActiveTextEditor` subscription that registers `window.tabGroups.onDidChangeTabs` + `onDidChangeTabGroups` listeners re-running the same resolver on active-tab changes. Those listeners must be registered at activation, not from inside the handler: `onDidChangeActiveTextEditor` only fires on text-editor changes, so a window whose tabs are all markdown editors never runs it and the feature stayed dead until you visited a text editor once. Each listener resolves synchronously and again on a macrotask, because a tab that has just opened isn't yet `activeTabGroup.activeTab` when the event fires; one pass also runs at activation for a window that starts on a markdown editor. A filePath dedup keeps the paths from double-firing. All three revert by stripping their sentinel blocks. (Opt-in debug: `touch ~/.ccaa-debug` then reload — each event logs the active tab's input type / viewType / uri / label to `<tmpdir>/ccaa-md-debug.log`.)
  - adds `ccaaQuickSend` — `getConfiguration("claude-code-no-auto-attach").get("quickSend")`, read each time — to every webview state the host builds (next to `spinnerVerbsConfig`, which upstream forwards the same way; the init and update payloads are built separately, so all of them), and adds `claude-code-no-auto-attach.quickSend` to the settings listener that re-posts that state (the one that checks `claudeCode.spinnerVerbs`), so a slot change reaches open sessions right away;
  - calls `globalThis.__ccaaVoiceHostStart(channelId, post)` first thing in the VS Code host's `handleStartSpeechToText` (not the base-class stub, which only throws). This extension then starts `claude -p --model haiku` from Claude Code's `resources/native-binary/`, with `--setting-sources ""` (no hooks, env or permissions from settings, and no CLAUDE.md), `--tools ""`, `--strict-mcp-config`, `--disable-slash-commands`, `--no-session-persistence`, its own system prompt, stream-json input and output, `MAX_THINKING_TOKENS=0` and `claudeCode.environmentVariables`. The process boots while you speak and waits for a transcript on stdin, 15 minutes at most. One process serves one recording and is killed after it, so recordings never share context. `post` sends to that panel's webview, for the mic check below;
  - calls `globalThis.__ccaaVoiceHostDone(channelId, transcript, post)` first thing in the `finally` of the loop that forwards `speech_to_text_message`s, i.e. once the stream ends, whether you stopped it or it ended by itself. Every message carries the whole transcript so far, so the loop's last value is the full text; `post` is `this.webview.postMessage`, the webview that recorded. This extension posts `cleaning`, writes the transcript to the process (or to a fresh one, when the start hook did not run), and posts `done` with the text inside Haiku's `<cleaned>` tags, or `failed` on an error, a 15s timeout, missing tags, or a text so much longer or shorter than the transcript that Haiku likely answered it. An empty transcript, the setting turned off or a missing binary posts `skipped` instead, so a held send goes out right away. Timings and failures (never the text) go to the output channel.
  - calls `globalThis.__ccaaMicStart()` in the recorder start function right before the native module's `startRecording(` (after its `isRecording()` early return), and `globalThis.__ccaaMicStop()` right after the matching `stopRecording()`. The native module (`audio-capture.node`) takes no device argument and opens the default input. So when `dictation.builtInMicrophone` is on, `__ccaaMicStart` synchronously runs a small CoreAudio helper ([mic-helper.c](mic-helper.c), built once with `clang` into the extension's global storage at activation, ~90ms per call). The helper makes the internal mic the default: the built-in device whose input data source is `imic`, since the headset jack ("External Microphone") is a built-in device too and prints the previous default. `__ccaaMicStop` puts that previous default back, and only if the default is still the built-in mic. A new default says nothing about the device the recorder opened, so `__ccaaMicStart` first starts the helper's `watch <pid>` command in the background. It asks CoreAudio every 10ms which inputs the extension host reads (`kAudioProcessPropertyDevices`, macOS 14.4+) and prints the first list it gets, 4s at most. It starts before the switch, so its own CoreAudio startup (~150ms) overlaps with the switch and the recorder start, and the answer comes in a few ms after the recorder has opened its input. When all of them are the built-in mic, the host posts `{type:"ccaa-mic",state:"builtin"}` to the panel that records. The voice lib then sets `body[data-ccaa-mic="builtin"]`, and the stop sends `state:"off"`, which clears it. Otherwise it logs the device names. Without `clang`, or off macOS, both hooks do nothing.

Every `.js` sub-patch is parsed (`vm.Script`, no execution) before it is kept, and the assembled file once more before it is written. An anchor can keep matching while the code around it changes shape — 2.1.261 turned the webview's `listSessions("panel_boot")` statement into an `if(…)` operand, and the statement injected in front of it left the whole bundle unparsable, i.e. a blank Claude panel. A sub-patch whose result doesn't parse is skipped and logged like a missed anchor, so it only costs its own feature; should the whole file still fail to parse, the clean upstream file is written instead and an error notification names the file and the parse error.

`node scripts/check.js` dry-runs all of this against every installed Claude Code version without writing anything (see [CLAUDE.md](CLAUDE.md)).

Each patched file is prefixed with a versioned marker so re-launches don't re-patch. When the patch logic changes the marker version is bumped, and `applyPatch` reverts any older marker before re-applying so the rollover is seamless. `vscode.extensions.onDidChange` triggers a re-apply whenever Claude Code updates.

## Settings

- `claude-code-no-auto-attach.detachContextByDefault` (boolean, default `true`) — start new Claude sessions with the current file/selection **not** attached as context. Set to `false` to keep upstream's attached-by-default behavior. Either way, `Ctrl+F` toggles the attachment while a Claude session is focused. Because this is baked in at patch time (the webview can't read VS Code settings), changing it re-applies the patch and prompts a window reload.
- `claude-code-no-auto-attach.autoApproveProtectedPathWrites` (boolean, default `false`) — auto-approve `Write`/`Edit`/`MultiEdit`/`NotebookEdit`/`Bash` prompts that fire against Claude's own protected paths despite `bypassPermissions`. The setting is mode-gated, but the gate only takes effect after permission mode is set/changed once in the session — toggle to `bypassPermissions` once at session start to arm it. The injected code reads the setting on every prompt, so toggling takes effect immediately — no reload needed. ⚠️ Only enable in trusted workspaces.
- `claude-code-no-auto-attach.sessionScopedModelSwitch` (boolean, default `true`) — make model switching session-scoped instead of rewriting the global default. Read on every switch, so toggling takes effect immediately. To change your **global default** model: toggle this OFF, switch the model in any session, toggle back ON — or edit the `model` key in `~/.claude/settings.json` directly.
- `claude-code-no-auto-attach.uriOpensInEditor` (boolean, default `true`) — make `vscode://anthropic.claude-code/open?prompt=…&session=…` URIs open/resume in the locked editor group you keep Claude Code in (creating and locking a side column when there is none) instead of hijacking the active editor group. Read on every URI, so toggling takes effect immediately.
- `claude-code-no-auto-attach.uriAutoSendsPrompt` (boolean, default `true`) — when such a URI carries a prompt (and `uriOpensInEditor` is on), submit it right away instead of just typing it into the composer. Waits for the session to be idle; gives up after 30s and leaves the prompt typed.
- `claude-code-no-auto-attach.sessionScopedEffortSwitch` (boolean, default `true`) — make effort switching session-scoped instead of rewriting the global default. Covers both the native effort picker and the effort the quick-send slots set. Read on every switch, so toggling takes effect immediately. The pick goes to the session's flag settings, which the CLI ranks above per-model defaults, so it holds for every model until the next pick. A resumed session gets back the effort of its last answer. To change your **default** effort, edit `~/.claude/settings.json`. Since Claude Code 2.1.280 a top-level `effortLevel` there only applies to models the CLI treats as legacy (e.g. `claude-opus-5`, `claude-sonnet-5`); newer ones such as `claude-opus-5-5` fall back to their own default (`medium`) unless `modelSettings` names them. Family aliases work as keys:

  ```json
  "modelSettings": {
    "opus": { "effortLevel": "xhigh" },
    "sonnet": { "effortLevel": "medium" }
  }
  ```
- `claude-code-no-auto-attach.voiceCleanup.enabled` (boolean, default `true`) — when a Claude Code dictation stops, have Haiku clean up the dictated text (fillers, stutters, broken words, fragments), leaving the wording otherwise alone. Read on every recording, so toggling takes effect immediately.
- `claude-code-no-auto-attach.dictation.builtInMicrophone` (boolean, default `true`) — macOS only. Record dictation with the Mac's built-in mic even when a headset is plugged in, by switching the default input for the length of the recording. Read on every recording, no reload needed.
- `claude-code-no-auto-attach.quickSend.<slot>.model` / `.effort` (`<slot>` = `purple`, `red`, `yellow`, `teal`) — the model (`fable`, `opus`, `sonnet`, `haiku`) and effort (`unchanged`, `low`, `medium`, `high`, `xhigh`, `max`) of each quick-send slot. Defaults: purple Fable · `high`, red Opus · `xhigh`, yellow Sonnet · `medium`, teal Haiku · `medium`. The Settings UI shows each slot's two dropdowns next to each other. Read at runtime: a change reaches open sessions without a reload.

## Caveats

- ⚠️ This modifies files inside another extension's install directory. Expect it to break if Anthropic significantly refactors their bundle. When that happens the extension logs the reason to the `Claude Code: No Auto-Attach` output channel and skips only the broken sub-patch, nothing destructive.
- ⚠️ VS Code doesn't currently verify extension integrity post-install, but if that ever changes this approach could stop working.
- ⚠️ `autoApproveProtectedPathWrites` bypasses Claude Code's protected-path safety check (covering `.claude/`, `~/.claude/settings.json`, etc.). Don't enable it in workspaces where you don't fully trust the agent.
- The model badge, `Ctrl+M`, `Ctrl+0/1/2/3`, and `Ctrl+F` handlers live inside the Claude webview, so the shortcuts only fire when a Claude session has focus (that's also what makes them target the right session). They're captured there (capture-phase + `preventDefault`), so while the session is focused `Ctrl+F` won't reach VS Code's find and `Ctrl+0/1/2/3` won't reach VS Code's focus-editor-group.
- The markdown-preview resolver re-runs when focus moves from a text editor to a preview, when you switch directly between preview tabs, and when a markdown tab is newly opened or already active at startup (it listens to active-tab changes, not just active-text-editor changes). Two identically-named `.md` files that are both closed can't be disambiguated by the tab label — in that case it falls back to upstream's clear/retain behavior.
- A window reload is required after the patch is applied; the extension will prompt you. Every window checks the patched files against the state they were in when its Claude Code host loaded them, so a window that was already open when another window (or a new build of this extension) rewrote the bundle is also prompted — without it that window keeps running the old, unpatched Claude Code code and features like the session-scoped effort switch silently look broken.
